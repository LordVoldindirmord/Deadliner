# Deadliner

##### **Персональный планировщик задач с веб-интерфейсом и Telegram-ботом.Позволяет создавать задачи с дедлайнами и приоритетами, группировать их по тегам, отслеживать статусы и получать сводку на дашборде.**



###### **Стек технологий:**

* Язык: C# (.NET 10)
* веб-фреймворк: ASP.NET Core MVC
* база данных: PostgreSQL
* ORM: Entity Framework Core (Database First)
* аутентификация: ASP.NET Core Cookies
* Telegram-бот: Telegram.Bot
* UI: Razor Views.



###### **Архитектура проекта:**

1. Deadliner.Domain — сущности базы данных, ViewModel для фронта, DTO для Telegram, перечисления (Enum). Не зависит от других слоёв.
2. Deadliner.DAL — уровень доступа к данным. Содержит DbContext и репозитории. Ссылается на Domain.
3. Deadliner.Service — бизнес-логика, валидация, вызов репозиториев, формирование BaseResponse. Ссылается на DAL и Domain.
4. Deadliner.ASP — веб-приложение на ASP.NET Core MVC. Контроллеры, представления Razor, статические файлы. Ссылается на Service и Domain.
5. TelegramBot — консольное приложение Telegram-бота. Использует те же DAL и Service, что и веб-приложение.



###### **Функциональность:**

1. **Веб-интерфейс:**

   * Регистрация и вход пользователей с хешированием паролей (BCrypt). Аутентификация через cookies.
   * Дашборд: счётчики активных, просроченных, выполненных и отменённых задач, ближайшие задачи с группировкой по тегам, возможность выбора количества отображаемых задач.
   * Управление тегами: создание, редактирование названия и цвета, удаление с каскадным удалением задач.
   * Управление задачами: создание с выбором тега, приоритета и дедлайна, редактирование, удаление, отметка выполнения. Детальный просмотр задачи со всей информацией.
   * Фильтрация задач: по тегу, приоритету, статусу, поиск по названию, показ только просроченных. Сортировка: по дедлайну, приоритету или дате создания, по возрастанию или убыванию.
   * Привязка Telegram-аккаунта: генерация одноразовой глубокой ссылки, активация через бота.
2. **Telegram-бот:**

   * Привязка аккаунта через глубокую ссылку с сайта.
   * Дашборд со счётчиками задач.
   * Просмотр активных задач с порядковыми номерами и кнопками выполнения.
   * Просмотр всех задач с отображением статуса, тега и приоритета.
   * Создание задачи: выбор тега из списка, ввод названия.
   * Создание тега: ввод названия, автоматическая генерация цвета.
   * Удаление тегов.
   * Текстовая команда для отметки задачи выполненной по реальному ID.
   * Постоянная клавиатура для быстрой навигации.
   * Команда отмены текущего действия.
   * Справка по всем доступным командам.



###### **База данных**

Подход Database First. Вместо типа ENUM используются текстовые поля с CHECK-ограничениями (в C# для этого используется как раз ENUM, чтобы соблюдать ограничение целостности).

Основные таблицы:

* users — пользователи (логин, email, хеш пароля).
* tags — теги (название, цвет, привязка к пользователю).
* user\_tasks — задачи (заголовок, описание, приоритет, статус, дедлайн, дата выполнения, привязка к тегу).
* telegram\_bindings — привязка Telegram-аккаунтов (токен, chat\_id, привязка к пользователю).
